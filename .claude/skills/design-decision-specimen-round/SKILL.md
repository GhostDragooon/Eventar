# An undecided frontend surface is answered by a specimen round, not by a built screen

Run the locked pipeline in `~/.claude/CLAUDE.md` first, then show every candidate as a labelled option on one dev-only specimen route. Ivan picks. The code does not.

- Route: a dev-only page under `app/dev-preview-uiport/`, gated out of production by the sandbox layout. Specimens use sample data and wire nothing into product screens. If the `show_pane` call answers that the session is not open in any window, the pane is not shown: put the exact URL and the route name in the reply and say where to look.
- Each option is a card showing its frames, the skill that argued for it, and what it costs. Put the recommendation first, with one line of reason.
- At least three options per surface. When skills disagree, give each skill's position its own option.
- Write the pick target to `docs/plans/mvp/PICKS.md` as `<surface> (<letter>): <option id>, <date>`. Downstream cards stay unstartable until their pick line exists.
- A motion option is a live sample on the same card list, not a prose spec alone. Put every motion option on one route with a switch, so Ivan can feel the difference. Replay the entrance by remounting the list under a key that changes with option, tab and run counter. Give each entrance animation a `prefers-reduced-motion` fallback. A scroll-driven option names its browser support in the UI and shows its content when unsupported.
- Before presenting motion, prove each option's animations run: `document.getAnimations()` names and durations per option, read in the Browser pane. A prose "no entrance animation" claim is unverified until those names match.
- Verify on the worktree's own :3100 server at desktop width, at 375 px (`document.documentElement.scrollWidth` must equal `innerWidth`), and in dark scheme. Read the console. Reset the tab afterwards per eventar-live-verify-worktree.
- Hand-back STATUS: `DONE (specimens), awaiting pick`. Do not mark the card done until the pick lands.
- Build every specimen from the real primitives in `components/ui` and the product's real classes and tokens. A look-alike re-typed from a product class string is not a specimen: it shows a design the product will not render. Before presenting, confirm each specimen imports the product component it stands for: grep each specimen file for its `components/ui` import. A file with no such import is a look-alike, and the round is not ready to present.
- Read contrast values only after every CSS transition has finished. In the Browser pane the animation clock can sit at 0, so `transition-all` Buttons report first-paint colours from `getComputedStyle`. Finish them first (`document.getAnimations().forEach(a => a instanceof CSSTransition && a.finish())`), then re-read. A probe that still prints "Measuring…" has no reading yet.
- A reviewer's contrast figure is a claim to re-measure, not a fact to put on a specimen. Re-measure in both schemes with transitions finished, cross-check against the token arithmetic in `app/globals.css`, and show the reviewer's figure beside the measured one. If they disagree because of the probe, withdraw the finding and say why.
- A specimen that stands in for a product overlay (modal scrim, drawer backdrop, menu surface) copies that class from the real primitive, not from memory. Grep it first (`grep -n -i -E "scrim|backdrop" components/ui/Dialog.tsx`); the 2026-10-25 UX-02 round guessed `bg-on-surface/40`, the primitive said `bg-on-surface/60`, and the specimen was corrected after the fact. Then check the overlay in dark scheme as well as light: a scrim that reads right on white can veil a dark page.
- Never apply a chosen option before Ivan picks it, and never pick for him.
- Align a specimen's columns by measurement, not by eye: after the edit and a reload, check that each element sharing a line has the same centreline and each element sharing a column the same left edge, then say so in the reply with the numbers. Use the `rendered-alignment-measurement` skill.
- While Ivan is iterating on a specimen's look, reload the route, show the changed frame, and stop. Run eslint, tsc, the 375 px sweep and the console read when he asks for them or says the frame is ready to commit. Launching them unasked mid-iteration got the run interrupted.
- Compressing a specimen card: fold a status into an existing row (the status pill sits beside the time, not on its own row), and keep the date cell a self-contained column. No full-width child may run across or under the date column. Measure card height before and after with `getBoundingClientRect` and report both numbers.
- The date cell is one fixed width on every card in the list, not sized to its content. Measure its `width` on all cards and report the spread (0 px means fixed). Selection tick boxes sit in a gutter outside the card, so they cannot push the date, the pill or the title.
- When Ivan names a paid or licensed component as the reference (for example "add the Card 4 block from React Bits Pro"), do not install it, enter a licence key, or copy its source. Follow its look and layout, write the code fresh from the project's own tokens and `components/ui` primitives, and present it as its own labelled option. If the licence blocks the source, say so in the reply and still build the fresh option.
- Before asking for a pick, re-check the round against the newest doctrine or IA doc in `docs/plans/` (any file dated after the round was built). If a doctrine changes the nav labels, the surface list or the home, the round is out of date: re-cut it under the doctrine first, or say in the reply that the picks describe a nav that will not ship. Do not present a stale round as ready.
- A pick can approve the recommendation and carve out an exception. Apply the option with that exception, record the exception on the PICKS.md line, and name it as a deviation. Do not turn it into a new option. Tables use an outer border only, not a full grid (Ivan, 2026-10-22).
- Before presenting a round, cross-check every "quiet call" or intro note against the option labels it describes. A note saying "the brand links to Registrations" beside option 5a linking to Events is a contradiction; grep the page for each named target after an edit.
- Re-cutting a round: prepend a dated `## RE-CUT <date> (supersedes everything below it)` block to the card doc with the status, my picks, the checks and what was retired. Leave the older `STATUS:` line underneath, labelled superseded, so only one live status exists.
