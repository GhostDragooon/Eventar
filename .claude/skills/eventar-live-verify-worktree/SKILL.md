# Eventar live verify: run the worktree's own server, seed and clean fixtures

Render the change from the worktree's own dev server on :3100 and read the result there. Never copy edited files into the main checkout at `/Users/ivan/Eventar`: peers share it, and a failed cleanup left the copies in place.

- Check ports first: `lsof -nP -iTCP -sTCP:LISTEN | grep -E ':(3000|3100|3200) '`. Never use :3000, which points at production.
- The default `eventar` preview config on :3100 runs review mode, which opens signed-out staff pages. Before trusting any auth walk, `curl -s -o /dev/null -w '%{http_code}' http://localhost:3100/events/new` with no cookie: 200 with the form means review mode is on. Sign in and probe the signed-in path; a signed-out pass proves nothing.
- Use only the local stack, `postgresql://postgres:postgres@127.0.0.1:54322/postgres`. Never read `.env.local` and never use the Supabase MCP.
- Seed a disposable org, an `organiser_admin` staff row and events, all titled or slugged `ZZ-…`, so cleanup is one delete per table. Seed SQL, probe matrix and cleanup: `references/fixture-seed.md`.
- Compare before and after on the same fixtures. Record HEAD's output before you apply the change, or check out HEAD in a separate worktree.
- Cleanup order: events, staff, organisation, then the auth user. Then query for leftovers and expect `events=0 staff=0 orgs=0 auth=0`.
- `audit_events` rows that a walk writes (a consent grant, a sign-in) stay. Audit rows are permanent by design (hard rule 11), so they are expected residue, not a cleanup failure. Name them in the hand-back.
- After cleanup, confirm the main checkout is clean with `git -C /Users/ivan/Eventar status --porcelain`. A guard can pass silently in zsh; see `shell-zsh-path-lists`.
- If the Playwright MCP refuses to start with `Browser is already in use`, or reports the profile locked by other processes, do not retry it. Run `ps aux | grep -i playwright-mcp` once to see the holder, and never kill it: the processes found in one walk belonged to other sessions and had different start times. Use the built-in browser tool and click by element ref: `find` or `read_page filter=interactive`, then click the ref or `form_input`. Coordinate clicks missed and used up most of one walk's budget. The built-in tool cannot choose a screenshot filename, so name each screenshot inline in the report. If the brief asks for a screenshot per step and the tool cannot write files, list each step with "on disk" or "not on disk"; a step inspected by text is not a screenshot pass.
- Sign-in, revoke and redirect checks need the `eventar-noreview` preview config. The default `eventar` config runs review mode, which bypasses auth, so it cannot exercise a revoke.
- Sign in as a disposable local test user by injecting its session cookies in the browser (localhost only). Write the cookies to a scratch file, never into chat. Delete the user and the scratch file afterwards.
- For a real magic-link sign-in, which needs no cookie injection, read the newest Mailpit message on the local stack (`curl -s 'http://localhost:54324/api/v1/messages?limit=1'`, then `/api/v1/message/<ID>`). Sleep about 3 s first, since delivery lags. Check that the message's `To` is the disposable user's address before using it, because the newest message may belong to a peer. Extract the link containing `verify`, write it to a `0600` scratch file, and navigate the browser to it. The link redirects to `/auth/callback` and lands on `/dashboard`. Read the account from the page afterwards. Never print the link or its token; delete the scratch file after the walk.
- Name the signed-in account from the page, not from Mailpit. The newest magic link shows which address was requested last, not which session the browser holds. On 2026-11-01 the staff shell showed no account or role, so the walk's persona was inferred from mail; say it is an inference, and read the role from the page before attributing results to it.
- Clear a stale auth cookie before a long browser run; it can make the page loop and hammer the server.
- A cold dev compile can exceed 6 seconds, so a blank card is not yet a bug.
- If :3100 to :3200 are all held by peer sessions, the live check is blocked. Record the change as not live-verified and name the first live check to run. Never fall back to :3000. Wait, then count RSC requests with `read_network_requests` before calling a redirect loop fixed or still present.
- A peer's claim lives in `scratch-demo/locks/dev-3100.lock` (session, task, timestamp). Read it with `cat` before starting a server. If a peer holds it, message that session (SendMessage) asking it to release the lock and keep :3100 running, then wait with a background watcher on the lock file, not a foreground sleep. Do not start a server or touch the Browser pane until the lock is gone, because the cookie jar is shared.
- Remove only a lock you wrote, and only after `cat` shows your session in it. Never clean up with `rm -f scratch-demo/locks/dev-3100.lock` (or any shared lock path) as a last step: a peer can write its claim after yours, and the blanket delete takes it too. Check before deleting, and if a delete may have hit a peer's lock, tell that session at once (SendMessage) so it can re-create the lock.
- Probe a server-rendered, zone-dependent value with curl before the browser: `curl -s -H "Cookie: eventar-tz=Asia/Hong_Kong" http://localhost:3100/dashboard`, then grep the header label and the stat tile. Run the probe on a preview config that sets TZ=UTC, which mirrors the Vercel server. Compare a few zones, an invalid zone (expect the UTC fallback), and no cookie. Output that changes with the cookie proves the code reads it.
- The organiser "today" zone comes from the `eventar-tz` cookie. A cold browser renders once in UTC, then self-refreshes once. Verify the cookie is written, and that a warm reload triggers no refresh.
- A hidden preview pane returns empty reads. Call `tabs_select` or take one screenshot to wake it before concluding the page is blank.
- A client page that never hydrates in the pane (buttons with no React props after about 12 s) cannot prove a click. Report the click step as not verified, not as "does nothing". Prove the server side with `curl` on the same cookie: logout returns 204, the old token then returns 403 `session_not_found`, and a fresh GET redirects to `/account/sign-in`.
- After every source edit, `location.reload()` the tab before measuring or screenshotting. The pane keeps the old render after a file changes on disk, so reads taken before the reload describe code that no longer exists.
- The browser cookie jar is shared with the main session and any browser subagent. Set or clear the cookie you test before each run.
- While a browser reviewer walks :3100, hold edits to source files the reviewed routes import (for example `lib/auth.ts`). Hot reload changes the screens under the reviewer mid-walk. Write the failing test first, then apply the fix after the reviewer reports.
- Custom create forms (`/events/new`) can ignore scripted value sets, and a keyboard pick of the venue option did not stick in one walk. Fill fields by clicking the ref and typing, mouse-click the venue option row by ref, and read the value back before submitting. This fix is not yet confirmed; record a failed fill as a finding with the exact field, not as a pass.
- An async autocomplete (a venue picker on a live geocoder) can rewrite its list 3 to 5 s after typing. Wait until `read_page` returns the same rows twice, then click the ref. A row swapped out between `find` and the click selects a neighbour: one 2026-11-01 walk clicked a Xizang venue and the event timezone silently became Asia/Shanghai. Read the timezone back after any pick, and record a changed timezone as a finding.
- Before any psql write, list the real table names (`\dt`, or `information_schema.tables`). Read columns the same way (`\d staff`) before a join: `staff` has no `user_id` column (2026-11-01: `ERROR:  column s.user_id does not exist`), so a persona-role lookup failed on its first query. A walk guessed `event_agenda_blocks`, which does not exist, and left the agenda step unwalked. The agenda table is `agenda_blocks`.
- Fixtures are clock-anchored. When local midnight passes, shift their start times by a day so they still straddle the boundary under test (for example 08:00 HKT). A stale fixture passes or fails for the wrong reason. A fixture whose start is in the past shows `Registration · closed` and takes no registration. Before a registration walk, read `status, start_time` back, then move `start_time` and `end_time` to a future time and reload. On 2026-11-01 the member fixture was set to `2026-12-04 01:00:00+00` before the practitioner could register.
- The in-app preview browser is pinned to HKT. To see an organiser in another zone, open a Playwright context: `browser.newContext({ timezoneId: 'America/New_York' })`, then wait for the `(GMT-4)` label before reading.
- The TZ=UTC preview config lives in `.claude/launch.json`. Add it only for the run and revert it before commit.
- A Browser-pane resize clears a viewport you set, without a warning in your own call. Take a fresh screenshot before any coordinate click, and set the size again only if the check needs that exact size.
- Reset the tab after any Browser-pane check. Viewport emulation and color scheme both persist: run `resize_window` with preset `desktop` and colorScheme `light`, then clear the theme key with `localStorage.removeItem('eventar-theme')`. A dark-scheme emulation survives reloads until it is reset.
- Dark theme in the app is set by the `eventar-theme` localStorage key, read on load. Emulating `colorScheme: dark` and setting `data-theme="dark"` on `<html>` both left `body` at `rgb(255, 255, 255)`. Set `localStorage.setItem('eventar-theme','dark')`, `location.reload()`, then wait about 1.5 s and read `getComputedStyle(document.body).backgroundColor` (expect `rgb(10, 10, 10)`) before judging dark frames.
- Narrow-width check: read `document.documentElement.scrollWidth` against `innerWidth` at 375 px. Equal values mean no horizontal overflow.
- Before/after proof: screenshot each state's crops and Read them, or embed both as base64 in one HTML grid and render it from `file://` in Playwright. `browser_run_code_unsafe` has no `fs`, so write the HTML from bash.
- A browser reviewer whose brief forbids starting servers cannot fix a dead :3100 itself. Before dispatching it, confirm `lsof` shows :3100 listening. If it does not, start the server under the lock first. If a reviewer hands back "blocked: nothing listening", start the server, take the lock, and SendMessage the same reviewer to resume. Do not spawn a new agent for the same walk.
- Check a signed-out public list page against the DB, not by eye. Count the card links in the HTML (`grep -oE 'href="/events/[0-9a-f-]{36}"' events.html | sort -u | wc -l`) and compare with the matching row count from `psql`. Then check that no title the DB marks as past appears in the HTML. Start the server only when nothing listens on :3100, under the lock, and say in the reply whether it is still running.
- A readiness watcher must exit non-zero when its timeout passes. A wait loop that falls through with exit 0 reports a dead server as a successful wait, and a completion notification then looks like a pass.
- Branches gated on `NODE_ENV=production` (missing-key errors, prod-only copy) never fire on a dev server. Build the worktree and serve it on its own port, one server at a time under the lock: `next build`, then `next start -H 127.0.0.1 -p 3200`. Name the mode in the hand-back.
- `/login` is magic-link only. To walk staff pages as a disposable `organiser_admin`, mint a session with `@supabase/ssr` `createServerClient` and `signInWithPassword`, using the local API URL and anon key from `supabase status -o env`. Write the cookie to a `0600` scratch file and send it as a `Cookie:` header. Confirm each staff route returns 200, not a 307 to `/login`, before reading it. Never print the cookie or the password. `browser_run_code_unsafe` echoes its whole script into the transcript, so a cookie embedded in the script leaks even when the scratch file is `0600`. Use a throwaway user only; delete the user and the script straight after the walk, and say in the hand-back that the cookie was echoed. Put the `filename` script under the worktree's gitignored `.playwright-mcp/` dir, as the 2026-10-25 walk did. Before each state of a two-server before/after, clear cookies: `localhost` cookies ignore the port, so the second server otherwise inherits the first server's session.
- A cron or dispatch tick acts on every event on the local stack, not only your `ZZ-…` fixtures. Count the rows it could write before the tick. After the walk, delete only the rows your run produced: match the error signature and exclude non-fixture titles (`... from email_log l using events e where e.id = l.event_id and l.error like '<signature>%' and e.title not like 'ZZ-%'`). Then confirm the count matches the seed.
- A send or destructive button may open a confirm dialog first. A walk that clicks once and reads the page sees no response and reports one. Check for the dialog after each click, confirm it, then read the status line. A "no response" finding on a button is unverified until the dialog step has been tried.
