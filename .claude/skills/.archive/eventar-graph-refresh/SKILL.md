# Eventar graph refresh: commit tracked outputs only

Refresh `graphify-out/` incrementally, then commit only the tracked outputs. Never commit the local backups.

1. Run `graphify --update` over git-tracked changes, then `graphify cluster-only .` to name the communities. macOS has no `timeout` binary; do not wrap the command in one. Run any Python that calls the graphify build functions (`extract`, `build_merge`, `cluster`, `to_json`) from a real script file under the session scratchpad, with an `if __name__ == '__main__':` guard, never a `python3 - <<'EOF'` heredoc: `extract()` uses multiprocessing spawn, and from stdin it fails with `FileNotFoundError: [Errno 2] No such file or directory: '<stdin>'`. Run the file with the interpreter in `graphify-out/.graphify_python`. Do not run a bare `graphify update .` when docs and code both changed: on 2026-11-17 it cut INFERRED edges from 873 to 87. For a code-only refresh, merge the AST extraction with the graphify build path (`build_merge`, then `cluster`, then `to_json`) and keep changed docs out of the manifest (step 6).
2. Judge health against the previous graph before calling anything a regression. The nine self-loop edges, all in `tests/rls/` and `tests/cpd/` files, were already there on 2026-10-15.
3. Stage and commit with a pathspec so peer-staged files stay out: `git add -- <paths>` then `git commit --only -- <paths>`. Add only paths that still exist: `git add` aborts the whole list if one path is missing or already staged as deleted. Pass deletions to `git commit --only -- <paths>` by path.
6. Code-only refresh: if changed docs get no semantic pass, leave them out of the saved manifest so the next refresh extracts them. Marking them seen first is the partial-update trap. Paths: `GRAPH_REPORT.md`, `graph.json`, `graph.html`, `manifest.json`, `cost.json`, `cache/stat-index.json`, and the `cache/semantic/*.json` files for changed sources.
4. Leave out the dated `graphify-out/YYYY-MM-DD/` backup folders and `.graphify_labels.json.sig`. Both are untracked local artifacts.
5. If a semantic chunk agent dies mid-run, check its `.graphify_chunk_*.json` before re-dispatching. A file written before the death can already be complete: validate it by script (parses as JSON, every node and edge has its fields). Merge a complete chunk; abort the update on a truncated one. Build the merge against `.graphify_old.json` (the pre-update backup), never the half-merged `graph.json`, and write `manifest.json` last.
7. Read each doc in line ranges, not one full read. A compressed read ("compressed to N words") drops sections and forces reconstructed nodes. Re-extract that doc by range before saving.
8. Verify claims by script before saving: for each table, migration or SECURITY DEFINER claim, grep the source file and correct the node when it disagrees. Last refresh: 73 definer claims verified, 5 corrected. Never hand-patch `graph.json` to fix a bad node, and never append a node or edge by script to link a new note; fix the extraction and re-run it. If the extraction cannot run, leave the link out and name the blocked step in handoff §0.
9. After every refresh, confirm `GRAPH_REPORT.md` still has `## Summary`, `## Graph Freshness` and `## God Nodes`. The last refresh wrote no Graph Freshness section, and the pre-work protocol reads that section. The report generator does not write that section: after regenerating `GRAPH_REPORT.md` from `generate()`, insert `## Graph Freshness` before `## Community Hubs` yourself, with the built commit (`git rev-parse --short HEAD`) and a note when the working tree has uncommitted edits. Then re-run the step-9 check.
10. The graph maps code and structure. Decisions and current status stay in the state doc. Ivan, 2026-11-14: "Graph stay code map. State file hold decisions."
11. Re-extracting a changed doc keeps node ids stable. Before dispatching the extraction, dump the existing nodes, edges and hyperedges whose `source_file` is that doc, and hand them to the agent with the rule: reuse each existing `id` exactly, re-emit every edge whose endpoints still exist, mint new ids only for new entities. Count the edges crossing the doc boundary before and after (`graph.json` `links`); on 2026-11-14 the boundary held 33 edges that a changed id would have orphaned. Verify every chunk by script (id format, `file_type`, `confidence_score` present and not 0.5, endpoints resolve to a node in the graph or the chunk) before merging.

Vault graph (the Obsidian vault is not a git repo, so its report has no Graph Freshness section; step 9 applies to the repo graph only). Its Decisions Log is too large to re-extract whole. Carry the existing nodes, edges and hyperedges whose `source_file` is that log over verbatim with a script, add the new section's nodes, then check the carried counts before saving. Last refresh carried 166 nodes, 337 edges and 3 hyperedges. Keep the script a file that takes the vault root as an argument, not a `sed` copy. A handoff's Closing line says "done" only for a step that ran as written. A carried-over or hand-merged vault graph is "partial": say so in the Closing line and in §0, and never mark the vault graph step complete on the strength of a hand merge alone.
