### `9154e5e` — CSS: unbreak `pnpm dev`

Discovered while trying to run the account-hygiene walkthrough live: `pnpm dev` returned 500 on every request. Root cause: Tailwind v4's default markdown source scanner was compiling a retired arbitrary-value CSS class quoted in `docs/plans/handoff_03092026.md` back into `globals.css` as an invalid `var()` rule; Turbopack's CSS parser then died.

Fix:
- `@source not "**/*.md"` in `app/globals.css` (Tailwind v4 directive; markdown/docs are documentation, not source of truth for class names).
- Rewrote the offending prose in `docs/plans/handoff_03092026.md` so no bracket-shaped Tailwind-parseable class name survives — neither in the handoff nor in the globals.css comment explaining the exclusion (that comment itself was scanned into the same broken output on the first attempt).

Dev has been broken since 2026-09-03 and would have ambushed the next session that ran `pnpm dev` locally.

### `7b12c1e` — Dev-local: auto-spawn inbucket

Discovered on the same walkthrough: Supabase CLI 2.109 marked the `[inbucket]` config section deprecated (in favour of a `[local_smtp]` block that isn't shipped yet), so `supabase start` no longer spawns `supabase_inbucket_Eventar`. 2. **`lib/supabase/server.ts` under `EVENTAR_REVIEW_MODE` clobbered attendee cookie sessions.** Returned the admin client unconditionally, so `/account` (and any attendee route calling `supabaseServer().auth.getUser()`) got `auth=null` even for a real signed-in attendee whose cookies were present. Attendee bounced to `/account/sign-in`. Fix: peek at the request cookies; if a Supabase auth cookie is present, use the cookie-bound anon client (real session honoured); otherwise fall through to admin (the actual review scenario — reviewer walking pages without ever signing in). Discovered while trying to walk Path A under `REVIEW_MODE=true`; verified live end-to-end after the fix.

## Environment lessons the next session should know

1. **`EVENTAR_REVIEW_MODE` breaks attendee flows unless the fix in `f406d4e` is present.** Under review mode, `supabaseServer()` USED to return admin unconditionally, so `/account` (which reads `auth.getUser()` server-side) saw null even for a real signed-in visitor and bounced them off. The fix peeks at cookies: real session honoured, no cookies → admin (actual review scenario).
2. **`GOTRUE_MAILER_AUTOCONFIRM=true` on local means the verify-email wall never naturally appears** — new magic-link signups are auto-confirmed. To live-walk Path C2 (resend verification) you need to admin-create an unconfirmed user or flip the env var; the SDK-level behaviour is proven either way.
3. **Local consent capture (F2) is not automatic** — walk-a-1 signed in via magic-link OTP and had zero rows in `consent_records`. `award_attendance_credit` correctly returned `skipped:missing_consents`. In production the sign-up flow captures ToS + privacy consents; on the OTP-only path there is no gate today. Product question, not a bug.
4. **The inbucket container guard from `7b12c1e` runs at `dev-local.sh` startup**, so next session should be able to `bash scripts/demo/dev-local.sh` and get dev server + mail catcher both up automatically. No scavenger hunt.
5. **CSS parse error was fully caused by markdown source-scanning** — the `@source not "**/*.md"` directive in `globals.css` prevents future regressions from the same class. If Tailwind v5 changes the directive syntax, review this rule.
