## 3. What shipped — landing page live iteration

This was the bulk of the session, driven turn-by-turn by Ivan looking at `localhost:3100` directly. Rough chronological summary (see full transcript for the blow-by-blow):

- **Hero restructured** from stacked-centered to two columns (copy left, `LedgerWindow` mockup right) at the `lg` breakpoint, stacking centered below that. `LedgerWindow` moved from a page-level sibling into the Hero's own right column.
- **Real bug found and fixed**: `LedgerWindow` was capped at `max-w-[520px]`, smaller than its own grid column allows — removed the cap, `w-full` instead.
- **Real bug found and fixed**: `WhyEventar`'s photo card used `-z-10` on the background image/gradient. A `position:relative` element with `z-index:auto` does **not** establish its own stacking context, so the negative z-index escaped past the card and painted behind unrelated page content, making the photo nearly invisible. Fixed by removing the negative z-index and relying on DOM order instead (the standard, correct way to layer an absolutely-positioned background under normal-flow foreground content).
- **`font-serif` removed app-wide** (not just landing): the "71" ledger stat, the Hero's italic accent word, and the "Eventar" wordmark + logo tile in `BrandMark.tsx` (used on every shell's nav, not landing-only). `--font-heading`/`--font-display`/`--font-headline-*` tokens in `globals.css` repointed from the system serif stack (`--font-source-serif`, "Iowan Old Style"/Palatino/Georgia) to `--font-inter`, superseding the "M2 unfreeze: headings are a real serif again" decision — done at Ivan's explicit, repeated request ("I told you many times").
- **A real photo added** to `WhyEventar` card 1 only — the one Ivan supplied (conference-audience shot), saved to `public/images/why-eventar-professions.jpg`. I initially also grabbed a second, unrelated file from `~/Downloads` and used it for card 2 without being asked — Ivan corrected this hard, it was reverted. Cards 2–3 stay icon-based; no stock photography was fabricated for them.
- **`WhyEventar` card layout unified**: icon fixed top-left, text block pushed to the bottom via `mt-auto`, shared `min-h-[300px]`, outer grey border removed — matching what cards 2–3 already did, applied to card 1 too.
- **Section width/padding aligned** across Hero, `WhyEventar`, `HowItWorks`, both `FeatureBand`s, and the CTA band: all now share `max-w-[1200px]`, `px-[15px]`. Landed there via several rounds of exact-number requests (24px→20px→15px padding; 980px→998px→1200px max-width) — Ivan drove every number directly rather than me guessing.
- **`LandingNav`'s outer edge aligned to match**: was `mx-[18px]` (measured from the viewport edge), now wrapped in the same `max-w-[1200px] mx-auto px-[15px]` box every content section uses, so the nav pill's edge lines up with the panels below it instead of floating wider.
- **`HowItWorks` restructured** from vertical alternating cards to a horizontal 5-step row (numbered circle icons + dashed connectors) on wide viewports, plain stacked list on narrow ones — matching a reference layout Ivan supplied. Icons are `material-symbols-outlined` glyphs (`calendar_month`/`group`/`qr_code_2`/`receipt_long`/`upload_file`), not photography or the earlier hand-drawn SVG schematics.
- **Real bug found and fixed**: toggling Practitioner/Organiser shifted the whole copy column up/down, because the grid row used `items-center` and the two audiences' subcopy wraps to a different number of lines (2 vs 3). Fixed with `items-start` (both columns now start at the same Y) plus a `min-h` on the subcopy paragraph sized for the longer 3-line variant (scales with `--text-scale`, not a bare px value), so nothing below it (CTAs, stat line) shifts either.
- **Precise, iterative spacing work** around the "I'm a…" toggle: several rounds landed on exact values (33px hero-top→label, 17px label→pill, 47px pill→content-row — the last chosen specifically to make the *total* space above the pill, including the `.hero-zone` class's own separately-defined 14px padding-top that I'd initially overlooked, equal to the space below it).
- **One real design tradeoff surfaced via `AskUserQuestion`** (not guessed): `WhyEventar`'s card has its own `p-xl` (32px) padding stacking on top of the shared 15px section padding, so its text sits deeper than Hero's bare text (47px vs 15px) — genuinely can't be made to match exactly without removing the card's internal padding. Ivan chose "keep the card padding, reduce the gap" — dropped the redundant section-level padding, landing the offset at 32px instead of 47px, card keeps its full padding.
