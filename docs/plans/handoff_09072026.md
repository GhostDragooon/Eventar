## Findings during plan-writing (caught by live verification, not assumed)

Two real gaps caught by querying the live Seoul project directly rather than trusting inferred signatures — both fixed in Sprint 3a's plan before it was called done:

1. **`write_audit_event`'s real signature has a `p_subject_type` param** that wasn't in any indirect reference read this session. Because the plan's draft used named-parameter calls, omitting it would **not** have errored — it would have silently written incomplete audit rows forever. Fixed, and the value (`'practitioner_licence'`) now matches the live table's own established convention (always a singular snake-case noun — confirmed by querying actual `subject_type` values in use: `'consent'`, `'event'`, `'registration'`, `'user'`).
2. **`app_private.require_active_staff` returns the calling `staff` row** (not void/boolean) — Task 6's spec now has the staff-gated functions capture and reuse that return value for the org-match check, instead of a redundant second staff lookup.

**Unprompted, separate finding — not part of this plan, flagged for whenever it's convenient:** the live `audit_events` table already carries roughly 200+ leftover synthetic rows from Sprint 1/2's own concurrency test suites (`chain_test_concurrent_0`–`199`, several `diag_batch_*`/`diag_concurrent_*`, one literal `forged`), permanently, because the table is append-only with no cleanup path. Harmless for an action log, but Sprint 3a's Task 9 flags that blindly copying the same test pattern for `credit_ledger` — meant to be a real, regulator-facing credit record — is a worse trade-off, and offers two options (a disposable Supabase branch for the stress test, or explicit synthetic-data discipline) rather than defaulting silently to what happened last time.
