### The scheduler (Stage 6's headline)
The 60-min reminder (carrying the QR pass people scan at the door) and the 10-min-after survey previously fired only when a human clicked them. `/api/cron/dispatch` now runs both on a schedule. Fails **closed** without `CRON_SECRET` (503 — a misconfigured deploy can never become a public mass-mail trigger). Accepts `x-cron-secret` or `Authorization: Bearer`, POST or GET.

Idempotency is delegated entirely to `email_log_dedup_idx` + Hard Rule 2's insert-first ordering — the insert *is* the lock. Proven against a real DB, and proven **non-vacuous** by dropping the index inside a rolled-back transaction (with it → `23505`; without it → the duplicate is written and the test fails).

**The `queued` arm, decided:** a `queued` row is TERMINAL under that index, so the dispatcher treats it as done-or-stuck, never "needs sending". A silent non-send is recoverable via the operator's existing manual button; a duplicate to a regulated practitioner is not. We take the recoverable failure.

## 3. Defects found — including one of mine

### Mine, caught by my own Stage 7 review
1. **The Stage 6 text-size fix was incomplete.** It swept `text-[Npx]` but missed **24 Tailwind default sizes** (`text-sm`, `text-xs`, `text-base`…), which are rem literals — including **every `ui/` primitive** (button, input, textarea). Every form control in the app was still unscaled. Fixed by overriding Tailwind's own size tokens once in `@theme` rather than editing 24 call sites; each keeps its paired line-height as a unitless ratio. This is the **fourth** time "the token layer only reaches components that use it" has bitten this codebase — the lesson is not learned until the grep for hand-rolled equivalents is reflexive.

### Pre-existing, found and fixed
2. **`email_log` held a table SELECT grant to `anon`.** RLS-with-no-policies was the *only* control in front of `recipient_email` (PII, Hard Rule 10). Empirically safe (anon reads returned `[]`), but it inverts this repo's own Hard Rule 11 lesson — RLS is not sufficient, revoke at the grant layer. Now `42501`. Same for `rate_limits`.
3. **`seed.sql` would have re-opened it on every `db reset`** — its blanket grant re-grants all tables to the API roles, so CI replay-from-zero and the future Singapore provisioning would both have produced a database with the PII grant live. Re-assertion added, exactly as the `staff`/`events` locks already do. **This is the same trap that re-opened the events column lock in July.**
4. **The door UI advertised `WK-XXXX`** (4 chars) in placeholder, hint *and* error, while real codes are 6 (`CODE_LENGTH = 6`). The regex accepts both, so validation worked — but an operator holding a `WK-HBQWDR` badge was told the wrong format at the one moment that has to be frictionless.
5. Two §7a colour violations (`text-red-700`, `hover:bg-gray-50`) and emoji-as-status-icon in two buttons. Replaced with the app's own material-symbol convention + `role="alert"`.
6. `handle_new_user`'s stray anon/authenticated EXECUTE — not exploitable (PostgREST won't invoke trigger-returning functions) but the last definer function inconsistent with the revoke discipline.

### Found, deliberately NOT fixed
- **`DEFERRED` item 56 — trigger FIRED.** `set_event_cpd_config` is `authenticated`-executable, so an organiser self-asserts accreditation against any active body. Every gate holds (role-gated, owner-checked, active-body-checked, ≤24h, columns still locked) — **not a security regression**. What's missing is the *product* model of which organisation may claim which body. Inventing one mid-review is how you ship the wrong model. **It blocks the first real accredited event.**
- **Dead code, reported not deleted:** `components/ui/{select,accordion,toggle}.tsx` have 0 importers; `lib/{withSecurity,abuseTier,attendeeAuth}.ts` are still unwired substrate; `users.locale` and `users.display_language` are both unread. Deleting working components is Ivan's call.

## 5. Verification state — what was proven and how

A full closed loop was run end to end on the local stack against an event created through the real UI: create → validate (end-before-start correctly rejected) → publish → accredit (PT_BOARD / 3h) → register → reminder via the scheduler → attendance → **CPD credit issued** (`credit_earned` / `attendance_verified` / 3h, idempotent on re-run) → freeze trigger blocked a `cpd_hours` change on the credited event while allowing an unrelated time shift → survey via the scheduler → feedback → analytics reflected every answer → both chains valid (audit 8/8, ledger 1/1).

**Honest limits of that run:**
- **Attendance and credit issuance were driven through the same RPCs the check-in Server Action calls** (real staff JWT), *not* by clicking the check-in screen. Browser auth kept wedging. The action's own wiring is covered by unit tests, but the button itself was not exercised.
- Time was advanced by moving the event's `start_time`/`end_time` in the DB, not by faking the app clock.
- Passwords were set on `demo-doctor@local.test` and `demo-staff@local.test` on the **local** stack to mint JWTs.
- The test event is now permanent local residue — deletion is blocked by `credit_ledger_event_id_fkey`, which is the intended regulator-grade property, not a bug.

## 6. Environment + workflow gotchas learned this session

1. **Background agents share ONE local Supabase stack.** The check-in-mode agent applied `20260803023000_events_checkin_modes_rpcs.sql` to it, but the file exists only in its worktree. `main` currently reads **79 local files vs 80 applied**. A `supabase db reset` on main right now would silently drop it. **Reconcile immediately after each merge.**
2. **The browser instrument wedges hard and lies.** 0×0 viewports, blank screenshots, dead `focus()`, and a React-fiber probe that suggested the page had not hydrated — it had; a fresh tab proved the app fine. This is the *second* time that exact false alarm has been recorded (see `handoff_02082026.md` §3). **A fresh tab survives roughly one full-page navigation.** `document.body.textContent` still works in a wedged tab when `innerText` returns 0. `find` never worked at all this session.
3. **Admin-generated magic links are not PKCE** — `/auth/callback` needs `?code=`, so sign-in must be initiated from the browser. Supabase also rewrites `redirect_to` to `site_url` (3100) if the target isn't in `additional_redirect_urls`; rebuild the verify URL by hand for 3200.
4. **`text-[calc(Npx*var(--text-scale))]` compiles fine in Tailwind v4** and is a provably zero-visual-change way to make a literal scale — unlike remapping to a token, which also drags in that token's line-height and font-weight.
