## 3. Phase-completion protocol — both lenses found real issues

**Dev-lens** (separate agent, full diff across all 6 build commits + live `has_table_privilege` checks against the running local stack):
- **Critical**, fixed in `e2ca94e`: `self_check_in`/`mark_attended` preserved the pre-multi-occurrence idempotency gate (`if status='attended' then already`) *before* occurrence resolution — once any occurrence's check-in flipped status, every later call for that registration returned `already` with zero symptom, and no second `registration_checkins` row was ever written. Traces to a gap in the **10.8 C2 design brief**, not the implementing agent — the brief asked for occurrence resolution but never re-examined whether the old single-check-in short-circuit still made sense once occurrence tracking existed. C4's own ICI-shape tests didn't catch it because they seeded `registration_checkins` directly via `sqlSuperuser`, bypassing the functions the bug lived in.
- **Important**, fixed in `e2ca94e`: `award_attendance_credit`'s `proportional` branch had a `v_available=0` guard but no `v_earned=0` guard — attending occurrences a group doesn't cover posted a permanent zero-value `credit_earned` row instead of skipping, inconsistent with `explicit_schedule`'s handling of the identical scenario.
- Everything else dev-lens checked (compatibility-bridge concurrency, the `LATERAL`/`NOT EXISTS` selection SQL, numeric division, per-group exception scoping, Hard Rule 11 grants across all 6 new tables, `seed.sql` re-assertion, `AwardOutcome[]` callers) came back clean.

**User-lens** (separate agent, cold-start through the real UI on `:3100`): the deadline advisory reads clearly, states plainly that it never blocks, and the UI/backend claim actually matches (saved successfully with a passed deadline, no dialog, no visual hint of blocking). One real, explicitly deferrable finding — see §4.

Both fixes independently re-verified by the orchestrating session too, live, through the real RPCs (not fixture shortcuts) — see the migration `20260815040000_multi_occurrence_checkin_fix.sql`'s own self-check plus manual multi-fixture backtests (ICI both-days, day-2-only, genuine tie, zero-earned skip).
