## Answers to the review questions

**1. `event_registration_eligibility`**
- Only the owner check changed [X]: the live `pg_get_functiondef` equals the migration text (the diff against the file is one trailing `;`), and the body diffs against `20260814030000` only at the gate (`created_by <> actor.id` became `organisation_id is distinct from actor.organisation_id`). `is distinct from` is also NULL-safe, which the old `<>` was not; both columns are NOT NULL anyway [X].
- `resolve_actor` already restricts roles to `organiser_admin`, `organiser_member`, `eventar_staff` and requires `status = 'active'`; its override branch fires only for `service_role`, so the cookie-client call with `p_actor_override` is inert [X def]. `body_admin` and `auditor` are refused, as before.
- Executed as `ux-member@eventar-review.invalid` (organiser_member, default organisation, not the creator) in a read-only transaction [X]:
  - soft-deleted event of the same organisation: 1 row returned (the function reads `public.events` as definer and does not look at `deleted_at`);
  - event of another organisation: `42501 event_registration_eligibility: event c8a043f3-... is not in your organisation`;
  - nonexistent id: `P0002 ... not found`;
  - as `anon`: `42501 permission denied for function event_registration_eligibility`.
- PII: `registration_id` and the enum only. See F13 for what the enum reveals.
- Grants: ACL `{postgres=X, authenticated=X, service_role=X}`, no `PUBLIC`, no `anon` [X]. The restatement is right and redundant (`create or replace` keeps the ACL).
- Two-row person: see F14.
