What it does:
- Migration: `mark_attended` and `self_check_in` refuse outside the check-in window and write nothing (no check-in row, evidence, audit event; status untouched; the rate-limit counter is still bumped, as before). The window: with ONE occurrence (every event the product creates) the EVENT's own `[start_time - 60 min, end_time]` decides, because an organiser edits `events.start_time/end_time` and nothing moves the occurrence row (its only trigger is AFTER INSERT): the first version of this card read the occurrence row and the dev and backtest lenses both found, independently and live, that an edited-then-published event was refused at its real start and accepted on its old date (6 of 132 local events had drifted; BLOCKER, fixed). With several occurrences (SQL-only today) each occurrence has its own window, open 60 minutes before its start until its end, and the one already started wins over one that is only pre-opening, whatever the ordinals. Outcomes: `closed` once the end has passed, `not_open_yet` otherwise (this replaces `no_matching_occurrence` for a gap; that string remains only for an event with no occurrence rows). The single-occurrence "any time" fallback is deleted. `self_check_in` keeps its event-level window; its multi-occurrence matching now has the pre-open. Grants restated and asserted (absent and present) in the file; the rollback note names single functions to restore.
- `markAttended` maps `not_open_yet` / `closed` to `checkInClosedMessage`; the staff surfaces (desk, staff scan action, walk-in dialog) share one voice via `checkInGateMessage`, including the walk-in dialog, which used to say "This event has not opened for check-in yet." and "... ended — walk-in registration is closed." The attendee's own pass page speaks to the attendee and keeps its own copy (the earlier docblock overclaimed; corrected).
- `walkInRegisterAndCheckIn` checks organisation access BEFORE the lifecycle gate (the 2026-10-09 finding), and when the check-in is refused after the person was registered (reachable now, e.g. a multi-occurrence gap) it says so: "<name> was registered (code ...) but not checked in. <reason>" instead of a bare check-in error that left a hidden registration (rule 12; both the dev and backtest lenses).
- The check-in desk follows a ticking clock that starts from the SERVER's clock (`serverNowMs` from the page, carried forward by the browser's elapsed time, re-read when the tab becomes visible): Scan badge, Enter code and each row's Check in are disabled with the reason when the server would refuse and enable or disable by themselves; a device clock that is minutes off cannot lock the door (dev review F2). The note is a `role="status"` region that stays mounted (screen-reader text "Check-in is open." when open), the rows point at it with `aria-describedby`, the walk-in dialog's refusal is `role="alert"`, and an unpublished draft's desk says "Publish the event before checking people in."

Known limits, stated:
- This is the function door. `authenticated` still holds column UPDATE on `registrations.status`, `check_in_at`, `check_in_method`, and the UPDATE policy has no status or time predicate, so a staff session can still mark attended through PostgREST at any time with no check-in row or audit event: DB-05 (the registrations UPDATE bypass), a stretch card. If DB-05 slips past the MVP a BEFORE UPDATE trigger refusing those changes from `authenticated` is a small interim guard.
- Re-scanning an already checked-in code outside the window now answers `closed` / `not_open_yet` instead of `already` (the window check precedes the idempotent insert).
- The attendee pass page is time-aware only at render: the early line does not tick and the "Pass ready" pill stays on in the early and closed states.
- The demo path (Beat 3, then `DEMO_START_OFFSET_MIN=-30` on the published event) is documented and, after the blocker fix, works by design, but was not rehearsed end to end (running the seed writes demo accounts into the shared local database).
