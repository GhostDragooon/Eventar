## What it does
- `event_registration_eligibility` (the roster's "will this attendance earn a credit" read) gated on `events.created_by`, so a teammate who did not create the event got 42501 and the roster told them "CPD eligibility couldn't be checked just now" (the 2026-10-10 user lens). It is a READ of the event's own roster: the gate is now "active staff of the event's organisation" (same roles through `resolve_actor`; `eventar_staff` any organisation). Another organisation's admin or member still gets 42501, now with "event ... is not in your organisation".
- The public read policy `events_public_read_published` was `status = 'published'`, and `softDeleteEvents` leaves status published, so a deleted event stayed readable by anyone with the anon key. It is now `status = 'published' and deleted_at is null`, in the one choke point. `agenda_blocks` and `event_occurrences` inherit it (tested); the accreditation tables inherit it by policy text (no local row to test). Organisation members keep seeing their own deleted events. The registrations INSERT policy (unreachable over PostgREST since SEC-01) also stops treating a deleted event as published.
- Scope of "private": reads through the anon key or a user JWT. Readers on the service-role client are untouched (see Needs Ivan 1).
- The eight accreditation and role WRITES that gate on `created_by` stay creator-only (Ivan's ruling 2, 2026-10-23). The matching UI tightening is NOT done by this card (pending Ivan's pick, UX-FU1 surface 5): a teammate now gets the eligibility readout, then the Chair/Presenter chips on the roster still fail with the creator-only message (user lens U3).

| Function | Kind | Disposition |
|---|---|---|
| `event_registration_eligibility` | READ of the roster | organisation-scoped (this card) |
| `add_event_accreditation_group`, `remove_event_accreditation_group` | WRITE accreditation | stays creator-only |
| `add_event_accreditation_row`, `remove_event_accreditation_row` | WRITE accreditation | stays creator-only |
| `link_accreditation_occurrence`, `unlink_accreditation_occurrence` | WRITE accreditation | stays creator-only |
| `set_registration_role`, `remove_registration_role` | WRITE roster roles | stays creator-only |
(`create_event_with_blocks`, `create_invite_token` and the `set_event_organisation` trigger mention `created_by` only to write it. No policy references it. Verified by the dev lens against the live catalog.)
