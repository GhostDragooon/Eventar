Investigated (so the decision can be quick) [X unless marked]:
- The data allows it: `staff` has `UNIQUE (email, organisation_id)`, so one email can hold two active rows.
- The three reads are `proxy.ts:94`, `lib/auth.ts:85` (`getStaffSessionState`, returns 'unknown') and `lib/auth.ts:144` (`requireStaff`, throws the Supabase error). All three use `.maybeSingle()`, which returns code `PGRST116` when two rows match [R: supabase-js behaviour, not executed here].
- On a staff route the proxy runs first, so the person sees `/login?error=unavailable` ("This is on our side, please try again in a moment") for ever. The page-level `requireStaff` read is only reached if the proxy let the request through (an attendee surface that calls `isStaffSession`); there the failure reads as an outage or is treated as fail-open attendee posture.
