## Per-question answers

1. SQL correctness (see also Verified OK).
   - Lock under INVOKER and RLS: `select ... for update` needs a column UPDATE privilege (`authenticated` has 23) and passes the UPDATE policy USING. Org admin and `organiser_member` (same org), `eventar_staff` in the same org, and `service_role` all pass the lock; executed in `proof2.sql` R1, R10, R14.
   - Check order and what each caller gets: array check (22023) first; then event not found or not visible (P0001); then organisation (42501, only when the event is visible to the caller, i.e. published or operator); then lock and status (22023 `event_not_draft`). Executed results: other-org admin on a draft gets P0001 (R8), on a published event 42501 (R9); operator from another org gets 42501 on both (R11); `anon` gets 42501 or P0001 (R12); same-org operator on a draft succeeds (R10); `service_role` succeeds on a draft and gets `event_not_draft` on a published event (R14).
   - Deleting omitted blocks: only rows of this event whose id is not in the payload, after the validation loop has proved every payload id is this event's own, unique. `id <> all('{}')` is true, so `[]` removes all blocks (executed, R2; matches the old function and the action comments). `v_ids` never holds NULL (appended only when non-null), so `<> all` has no NULL trap. A malformed id raises `22P02` (R3, R18), unreachable from the app because Zod checks `.uuid()`. A block of another event is refused (R4), a duplicate id is refused (R5).
   - Concurrent saves of one draft serialise on the event row lock taken first; READ COMMITTED gives each later plpgsql statement a fresh snapshot, so the second save sees the first save's committed blocks. Both lock the event row before any agenda row, and neither `publish_event`, `bulk_update_event_status` nor `set_event_cpd_config` writes `agenda_blocks` (checked in the catalog), so I see no lock-order cycle. [I] for the interleaving, not executed with two sessions.
   - Display order is the payload index (R1: ids kept, order 0/1/2). `topics` null handling: F8.
   - Helper: `security definer`, `search_path = public, pg_temp`, table schema-qualified, `anon` and `public` revoked, `authenticated` and `service_role` granted (catalog: `{postgres=X,authenticated=X,service_role=X}`). Issue: F5.
