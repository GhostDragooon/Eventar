# DB-05 backtest review (live behaviour, local stack only)

Reviewer lens: backtest. Local stack only: PostgREST http://127.0.0.1:54321, psql :54322, dev server :3100 (public registration only). Real signed-in JWTs: ux-admin and ux-member by magic link (OTP request, Mailpit, verify link without redirect, access_token from the fragment); ux-body the same way. The operator, the linked-account user and a second-organisation admin were disposable fixtures with password sign-in. No repo file other than this one was edited. No Seoul, no MCP, no browser, no `.env.local`.

## Verdict

The card does what it says. Nothing found that blocks it and nothing major. The UPDATE bypass is closed for every column and every API role I could reach it with; the roster edit enforces its organisation, role, link, clash, validation and no-op rules against real sessions; every legitimate writer of `registrations` still works after the revoke. Two minor findings and six nits, none introduced by a defect in the migration. The one that deserves Ivan's attention is F1 (an email correction can be consumed by an account claim and then cannot be undone).

Count line: 0/0/2/6 (B/M/m/n).

Two things in this run that look like product bugs and are not, so nobody chases them: (1) my first cross-organisation attempt returned 204 because my fixture was wrong, not the function: `set_event_organisation_trg` forces `events.organisation_id` to the creator's organisation on insert, so my "organisation 2" event was really in the default organisation. I rebuilt it with an organisation-2 creator, confirmed the event's organisation, and every cross-organisation probe below is from the rebuilt fixture. (2) My first public-registration attempts failed on my fixtures (Zod's strict UUID rejects my hand-made `db05b700-...` ids; an event that has already started is "closed"). Re-run with random v4 ids on a future event, they pass.

- Staff `markAttended` and `walkInRegisterAndCheckIn` Server Actions over HTTP (needs a staff cookie). Their database call, `mark_attended`, was exercised directly.
- The auditor role (same gate as body_admin, which I did test); an inactive staff row as actor.
