### Schema-naming gotchas worth remembering for the next session's SQL probing

This session lost three round-trips to guessed column names. Documented here so the next session doesn't repeat:

- `public.events`: time columns are **`start_time` / `end_time`** (not `start_at`/`end_at`). Capacity is **`max_attendees`** (not `capacity`). No `registration_opens_at` / `registration_closes_at` — registration is implicitly open until `start_time`.
- `public.registrations`: timestamp is **`registered_at`** (not `created_at`).
- Default habit: `cat supabase/migrations/<table>_init_*.sql | head -30` before writing any new query against an Eventar table.

### What ran

Seeded REPRO-PUB (`cca2897f-3d2e-417e-9bff-ca54b0ed22b6`) by pushing `start_time` to now+2h, `end_time` to now+4h, and inserting two registrations (`WK-BTST`, `WK-CAP2`) — the second one bringing the event to `max_attendees=2` capacity so A3's "registration closed" gate fires without waiting for `end_time` to pass. The user drove the click-through; I observed via SQL.

One snag worth recording: my first seed code was `WK-FILL`, which is **format-invalid** — the alphabet in `lib/registrationCode.ts` excludes `I` and `L` (visually-unambiguous chars only: digits 2–9 + uppercase minus `0 O 1 I L`). The page correctly rendered `Code not recognised` via the format check, which incidentally re-verified `isValidRegistrationCode` rejection at the page boundary, but it meant the *action-return* path for A2 wasn't actually exercised on the first pass. Re-seeded as `WK-CAP2` and re-ran step 5–6. Lesson: any future SQL-seeded codes must respect the 31-char alphabet; `WK-` + 4 chars from `23456789ABCDEFGHJKMNPQRSTUVWXYZ`.
