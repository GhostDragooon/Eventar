## Architecture decisions worth remembering

1. **Two-layer split with surfaces.** Layer 1 (attendance funnel — registered / attended / capacity / arrival latency) lives on `/dashboard` only. Layer 2 (5 survey questions + rule-templated insight narrative) lives on `/events/[id]/analytics` only. Per Decisions Log Q16 Decision A. The mockup deliberately omits Layer 1 from the per-event page; we honored that.

2. **No RPC, no migrations.** Phase 6 is read-only. The analytics route reads `events + registrations + survey_responses` in three parallel `Promise.all` queries via `supabaseServer` (RLS-aware). The dashboard adds two aggregate queries with `event_id IN (visible_ids)` joined to the event list in JS — O(2) round-trips regardless of event count. Both surfaces compute distributions via the pure helpers in `lib/analytics/`, never via SQL `GROUP BY`. The motivation was specifically to avoid re-triggering the `search_path`-pin lesson from the Phase-4.6 RPC fix.

3. **No role-branching in UI code.** The same components render for organizers and managers. RLS at the database determines visibility (organizer-own via `*_organizer_select_own`; manager-all via `*_manager_select_all`). Per Decisions Log Q16 Decision B + the user's direct instruction "no need to worry too much about manager or organizer, just add everything."

4. **Visual framework adopted wholesale.** User supplied a locked mockup at `docs/plans/phase-6-analytics-q2-mockup.html`. Only three substitutions where the framework's literal content couldn't apply against our data: Q2 speaker-rating → Latest Highlight + Comments count (we have free text); Q3 4th slug "Org/Flow" → 3 bars (we have 3 slugs); Q4 "Bench: 84%" line → dropped (no benchmark data source). All other styling — TopAppBar, hero, 5-slice card, slice anatomy, icon language, bar treatment, Q4 segmented + legend, Q5 `bg-primary/5` highlight, bottom info-card containers — verbatim from the mockup.

5. **Empty-state semantics surfaced by both review legs.** The dev-lens review caught `narrative.ts:11-13` coercing null `happyRate` to 0 via `?? 0`, producing "100% neutral/negative sentiment" copy when reality was "no Q4 data." The user-lens review caught the same bug at the visual layer — `SentimentSlice` rendered a 0%-width bar + four (0%) legend items. **Both surfaced the same underlying issue from different angles.** The single-commit fix (`cc17162`) now guards both layers + adds explicit zero-state branches to the narrative (showUpRate=0 / responseRate=0 produce dedicated copy). 4 new tests cover the branches.

6. **Dashboard row routing is status-aware.** Draft events route to `/edit` (organizer is mid-build, no analytics to show). Published / completed route to `/analytics` (live data). Found by user-lens F-U7 — without this guard, an organizer mid-draft would have hit the analytics page with all-zero metrics and the rule-templated narrative would have read "your event flopped" copy. The fix is a one-line ternary on the per-row `<Link>` href.
