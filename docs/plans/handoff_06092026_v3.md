### Two real bugs caught by the protocol (not by static review)

1. **A migration bug that would have broken every event create/edit in production.** `authenticated`'s INSERT/UPDATE on `public.events` is an explicit **column-level** grant (from `20260802182411_events_status_definer_only.sql`, tightened by `20260804030000`). Naming `format` in the RPCs' insert/update column lists without adding it to that grant makes Postgres refuse the **whole statement** — not just the new column — with `permission denied for table events`. `pnpm test:rls` caught this immediately (11 failing tests, all in files that create/update events, none of them format-specific — the tell that it was a grant issue, not a logic bug). Fixed in two places: the migration itself (`grant insert (format), grant update (format) on public.events to authenticated`) and `supabase/seed.sql`'s own **duplicate** column whitelist — that file runs a blanket `grant select, insert, update, delete on all tables ... to anon, authenticated, service_role` on every local `db reset` (a defence against a Supabase CLI 2.109 grant-zeroing bug, see memory `eventar-local-stack-cli-2109-grants`) and then re-narrows `events` back down to its real whitelist, which also didn't know about `format` yet. Both fixes are asserted live in the migration's own self-check via `has_column_privilege`.
2. **A live-event categorization bug**, caught by actually looking at the seeded fixture data in a browser rather than by unit test (the unit tests all used fabricated `startMs` values that happened not to expose it). The Upcoming/Past split used `e.startMs >= nowMs`, which is false for any event whose `lifecycle === 'live'` (a live event's start is, by definition, in the past). Both seeded review-mode fixture events are `live`, and they were filing under "Past" — a genuinely broken, misleading state for the one class of event a dashboard most needs to surface correctly. Fixed: `lifecycle === 'live'` now always counts as Upcoming, in both the Upcoming and Past filter branches (so the sets stay a true partition, no event double-counted).
