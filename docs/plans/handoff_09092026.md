Two real gaps remained, plus terminology drift:

### 1. `/auth/callback` error redirects ignored audience

The shared magic-link callback's error paths (missing `code`, failed `exchangeCodeForSession`) unconditionally redirected to `/login` — the organizer door — regardless of which audience initiated sign-in. Fixed by deriving the error destination from `?next=`:

```ts
const errorBase =
  rawNext?.startsWith('/account') || rawNext?.startsWith('/events/')
    ? '/account/sign-in'
    : '/login';
```

The `/events/`-prefixed branch was **not** in the original fix — the public event page's own sign-in link round-trips as `?next=/events/[id]`, not `/account`. Both the dev-lens and user-lens review agents independently traced every `/auth/callback?next=` caller and caught this gap before it shipped. Verified against the full closed set: attendees send `/account`, `/account/claim`, or `/events/[id]`; staff sends `/settings` (organizer email-change) or nothing at all.

### 2. `/account/sign-in` soft-loop

A signed-in-but-unauthorized session (valid Supabase auth, no matching `public.users` row) could loop: land on `/account/sign-in?error=...` → the page's existing session-check `useEffect` sees a valid session and auto-redirects to `/account` → fails again → back to `?error=...` → repeat. Fixed by lazy-initializing `sessionKnown` to `Boolean(urlErrorCode)`, which skips the session-check effect entirely and renders the form + error banner immediately.

```ts
const [sessionKnown, setSessionKnown] = useState(() => Boolean(urlErrorCode));
useEffect(() => {
  if (urlErrorCode) return;
  // ...existing session check...
}, [router, next, urlErrorCode]);
```

(First-pass version called `setSessionKnown` synchronously inside the effect body — caught by `react-hooks/set-state-in-effect`, restructured to the lazy initializer above.)
