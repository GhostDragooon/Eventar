## 1. The headline: the plan was wrong, and the source said so

Ivan wrote a 2026 dual-track launch plan. Rather than working from its paraphrase, I read the actual **HKAM Principles and Guidelines on CME/CPD, Cycle 2026-2028** (EC 07.01.2025, `~/Downloads/CMECPD Guidelines 2026-28.pdf`). It contradicts the plan in four places:

| Plan said | §  | Source says |
|---|---|---|
| Event-level `participation_type`, frozen at CPD config | 6.1 / 6.2 | Attendee (1pt/h, ≤75/cycle) and chair/presenter (3 or 6 pts) are **different categories at the same meeting**. It is a property of a **person's role**. |
| 2×2 taxonomy + Ethics boolean | 6.1–6.16 | **Sixteen categories**, each with its own caps and non-overlap rules. "Medical Professionalism & Ethics" is an *example inside* §6.16 (≤5 pts/cycle), not a third axis. |
| `unique (user_id, track) where is_primary` | 4(b) | A Fellow with Fellowships at **two Colleges must satisfy each separately**. Both are `track='hkam'`, so per-track reproduces the defect it replaced. |
| Platform `cpd_hours <= 24` | 7 | **Each College** sets the max hours accreditable for a single FCAA. |

Also: the cycle return goes **College → Academy Education Committee → MCHK** (§2(d)), not College → MCHK. The export was designed for the wrong consumer.

**Why this mattered:** the old model would have written under- or over-credited points into **immutable ledger rows** for every accredited meeting with a chair. Discovery path: a College, at cycle-end. Corrections on an append-only hash-chained ledger are compensating entries, not edits.

Recorded in **`docs/adr/0001`**. Vocabulary in **`CONTEXT.md`** (glossary only — keep implementation detail out of it).

## 2. What that changed

- Category moves to **`registrations.fcaa_category`**, default `'6.1'`; store the regulator's code in `credit_ledger.category`.
- Primary licence index becomes **per body**, not per track (a College *is* a body).
- Per-event hours ceiling moves into the rule pack.
- **No event-level category column** — the registration default *is* the suggestion.

## 3. The finding that keeps the whole thing cheap

`award_attendance_credit` **already selects the registration row** (`20260725144725:49-50`). Widening that select to `fcaa_category` and `minutes_attended` means **no signature change** — so no `drop`+`create`, no re-granting from scratch, no re-applying the `lock_timeout` ALTER from `20260804020000`, and no edits to `lib/cpd/awardAttendanceCredit.ts` or its three callers. `record_credit_entry` already has `p_points` and `p_category`.

Combined with using the already-hashed, permanently-NULL columns (`points`, `category`, `reason`) and unconstrained `hours`, **the entire credit path needs zero new ledger columns and zero chain-versioning.**

Rule packs live in **`accrediting_bodies.category_taxonomy`** — an existing `not null` jsonb whose seed comment already says "each College sets its own taxonomy on partnership". The SQL award function reads it and snapshots **result + pack hash as values, never a reference** — which is the only thing keeping doctrine **D.1** intact. ⚠️ If a future change ever stores a `category_taxonomy` row id on a ledger row, D.1 breaks and Q26 stops being deferrable.
