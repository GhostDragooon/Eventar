# Handoff — 2026-09-07 — Dashboard route split: Programme + Manage

**Commit:** `16dadaa feat(dashboard): split /dashboard into Programme + Manage routes`
**Branch:** `main`, pushed to `origin/main`.

## What shipped

The single `/dashboard` page — which combined a programme calendar (agenda, metrics, needs-attention feed) and a full admin console (lifecycle tabs, search/sort, bulk ops, per-row deep links) — is now two routes:

| Route | Job | Component |
|-------|-----|-----------|
| `/dashboard` | **Programme** — org-facing schedule: what's on, when | `DashboardWorkstation` (trimmed) |
| `/dashboard/manage` | **Manage** — event management workhorse: find any event, jump into ops | `ManageWorkstation` (new) |

StaffShell sidebar now shows **Programme** (`calendar_today`) and **Manage** (`event_note`) instead of a single "Dashboard" entry. `isActive()` uses strict equality, so `/dashboard/manage` does not highlight Programme.

### Structural changes

- **`app/dashboard/data.ts`** (new) — shared `fetchDecoratedEvents(supabase, nowMs)` returning `{ events, registered7d, checkedInToday }`. Both pages call it; attention items + CPD pulse metrics stay in `page.tsx` only (the manage page has lifecycle tab counts that serve the same purpose).
- **`app/dashboard/manage/page.tsx`** (new) — `requireStaff()` at top, `fetchDecoratedEvents()`, wraps in `<StaffShell>`. `force-dynamic`, metadata title "Manage events".
- **`components/dashboard/ManageWorkstation.tsx`** (new) — full manage panel extracted from DashboardWorkstation. Lifecycle filter tabs with counts, search, sort, bulk ops (CSV/Delete/Cancel/Restore), per-row action links (Details, Edit, Check-in, Analytics, Delete).
- **`components/dashboard/DashboardWorkstation.tsx`** (rewritten) — programme-only: ~400 lines of manage code removed. Keeps programme header, needs-attention, events agenda with calendar, pulse metrics. Added "Manage all events →" CTA link to `/dashboard/manage` after pulse metrics.
- **`app/dashboard/actions.ts`** — added `revalidatePath('/dashboard/manage')` alongside existing `revalidatePath('/dashboard')` so bulk actions revalidate both views.

### Per-row action links on Manage

Each event row now has 5 actions:

| Action | Target | Type |
|--------|--------|------|
| Details | `/events/[id]/details` | Link |
| Edit | `/events/[id]/edit` | Link |
| Check-in | `/events/[id]/checkin` | Link |
| Analytics | `/events/[id]/analytics` | Link |
| Delete | soft-delete + ConfirmDialog | Button |

## Bugs caught and fixed by the two-agent review

1. **Duplicate registrations query** (dev review, HIGH) — `page.tsx` re-fetched registrations that `fetchDecoratedEvents` already fetched, producing a second round-trip and an unguarded `.in('event_id', [])` on empty arrays. Fixed by computing `checkedInToday` inside the shared `data.ts` function and returning it.

2. **"Door" label** (user review) — cryptic jargon; renamed to "Check-in" to match the sidebar label and route name.

3. **"Archive" vs "Delete" wording disagreement** (user review) — bulk button said "Archive" but the dialog said "Delete N events?" and the toast said "moved to Deleted". Renamed the button to "Delete" with the delete icon.

### User-review flags NOT fixed (design decisions, not bugs)

- Sidebar label discoverability (Programme/Manage less discoverable than a single Dashboard entry)
- CTA visibility ("Manage all events" could be more prominent)
- Keyboard accessibility gaps (calendar subscription `<span>`, account chip)
- Draft event visibility on Programme view
- CSV export feedback (no progress indicator)

All noted for future sessions; none were requested as immediate fixes.
