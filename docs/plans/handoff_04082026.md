## 6. The three-lens review — and what it found in the same day's work

**Both criticals were in code written this session, and both are the same class: a control placed one layer above where the write actually happens. That is the fifth instance in this repo's history.**

1. **The DEFERRED-56 gate was bypassable in two statements, live.** It reads the event's `organisation_id`; `authenticated` held column INSERT+UPDATE on it and `events_organizer_update_own` constrains only `created_by`. Refused → PATCH the event into the default organisation (holder of every authorisation) → accredit. Raw PostgREST, no Server Action. Closed by `20260804030000`: the column is revoked from every app role and a `BEFORE INSERT` trigger derives it. A trigger rather than an RPC edit, because `create_event_with_blocks` is SECURITY **INVOKER** — naming the column would check the invoker's privilege on the column being revoked.

   This also fixed a **latent multi-tenancy bug** found independently by the backtest: because nothing ever set `organisation_id`, every event created through the product landed in the Default Organisation regardless of tenant. Latent at one tenant (Seoul has exactly one), wrong at two.

2. **`mark_attended` minted attendance *and permanent credit* on a cancelled registration.** DEFERRED 57 fixed only the self-serve door, so the two doors disagreed about the same person in the same second — and the staff door is the one that mints credit. The July review's guard (5b) was written as the compensating control for exactly this and **has been vacuous since it shipped, on both paths**: check-in commits `status='attended'`, then award reads a separate RPC and never sees `'cancelled'`.

**Also closed:** `seed.sql` re-opened the new allow-list table on every `db reset`; the DEFERRED-56 regression suite ran under **no gate at all** (skipped by `vitest`, not collected by `test:rls`); the accreditation picker offered 7 unusable bodies out of 9 and blamed the wrong thing; `not_open` told late arrivals to wait for a moment that had passed; a cancelled registration rendered a green "Pass ready" pass; any backend error at the door rendered as "Code not recognised"; `publish_event` was not idempotent; `credit_disputes`' resolution fields sat one policy away from self-resolution.

**Verified clean by the review:** the reconcile migration lost no behaviour from either original · `search_path` pinned on all 30 definer functions on both databases · audit-insert-last holds in all 16 · lock timeout works with no partial writes and no deadlock path · `get_advisors` no new criticals · RLS on all 19 tables.
