## Architecture decisions worth remembering

1. **Phase-completion-protocol applied at scale.** Every code commit in the R1, Q19, and Phase 7 batches went through static gates + (for the substantial ones) a backtest. The new pattern for Phase 7's facade integration was DB-truth verification (RLS policy inspection via `pg_policies`) for the Q19 swap, mock-based unit tests for the facade, and end-to-end inline review for the integration.

2. **Q4 reversed by Q19 (2026-06-02).** Managers are strictly view-only. Check-in is owner-exclusive. The "manager roams between rooms with a tablet" use case is now out of MVP scope; the answer would be "delegated co-organizer invites on the event," not "elevate manager privileges globally." See vault `02 — Decisions Log#Q19` for the full access matrix.

3. **Production-first + parallel-temp pattern for credential-pending integrations** (Phase 7 brainstorm direction). When the user wants to ship infrastructure ahead of credentials, the right architecture is two parallel files (real + stub), env-switch picker INSIDE the action (not at module top, for testability), and a documented removal protocol. The temp file's removal cost = the design metric. Pattern is reusable for Phase 9 (cron integration before pg_cron is live) and future external-service additions.

4. **Q18A/B patterns remain load-bearing.** Every new mutation Server Action in this session followed: RLS-gated `.update()` chains `.select().maybeSingle()` + null-check; mutations call `revalidatePath()` for every route that displays the affected data. Codified in CLAUDE.md and PROJECT_STATE's CARRIED-FORWARD.

5. **Lazy env reads inside Server Actions** (Phase 7 design). `process.env.RESEND_API_KEY` is read per call inside `sendEmail` and `registerForEvent`'s env switch, not captured at module load. Costs one negligible env lookup per call; enables per-test env manipulation without `vi.resetModules()`.

6. **`vi.hoisted()` for cross-references between `vi.fn()` and `vi.mock` factories.** Discovered during Task 5's test setup — `vi.mock` factory closures over `let`-declared `vi.fn()` refs throw TDZ ReferenceError. `vi.hoisted(() => ({ fn: vi.fn() }))` is the vitest 4 idiom. Worth knowing for any future Server Action test that mocks dependencies.

7. **`@react-email/components` deprecation finding (Task 1).** The package is marked deprecated upstream; Resend now points to `@react-email/ui` as the successor. Decision was to ship Phase 7 with the deprecated package (it's the latest version, Resend maintains it, only one template uses it) and migrate as a small post-Phase-8 follow-up. Documented in commit `2a0a73c` body + PROJECT_STATE CARRIED-FORWARD.
