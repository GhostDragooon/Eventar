## 3. Defects found — and which ones I caused

**Live verification found every one of these; the static gates passed clean throughout.** That is the load-bearing lesson repeating from the CPD MVP build.

### Caused by me, in this session

1. **WCAG AA regression.** Adopting `#0E79EC` for filled CTAs took every primary button from 4.55:1 (passing) → **4.23:1 (failing)**. Fixed to `#1C3C94` = 9.89:1. Root cause worth internalising: the app used **one** blue for everything; the locked design is a **ramp with roles**. Taking the values without the role separation silently downgrades contrast. The spec even said `#0E79EC` is "not small text".
2. **Hydration mismatch on every first load** — stamping `.light` pre-paint diverged from the server. Fixed by server-rendering `light` and marking the two intentional divergences.
3. **Silent-failure violation (rule 12), mine.** A "degrade gracefully" swallow hid a wrong column name (`name` vs `full_name`) and rendered an empty picker that read as *"this deployment has no accrediting bodies."*
4. **Alignment regression** — the shell's `<main>` lost `mx-auto` in the Stage 2 rewrite; content sat left of a 1440px column above ~1690px. My Stage 2 review missed it because I only tested at 1280px.
5. **`aria-label="Primary"` on the `<aside>`** — a complementary landmark — leaving the real nav landmark anonymous.

### Pre-existing, found and fixed

6. **The `NewEventForm` flake — root-caused after 7 occurrences.** The test's own comment claimed it waited for the button to re-enable; `findByRole` resolves on element *existence*, and the button is merely `disabled={pending}` mid-transition, so under load the second click hit a dead button. **Closed. If it reappears it is a NEW bug.**
7. **An event bound to a non-`active` body displayed as "Not accredited"** and would have cleared a real accreditation on save. True of the seeded data (bound to HKAM, `deferred`).
8. **Pre-hydration clicks did a native GET**, leaking form fields into the URL and silently doing nothing. Rewired to `useActionState`.
9. **The sidebar's "Events" link ejected users out of the staff shell** into the public site.

### One false alarm, recorded deliberately

A React-fiber probe suggested the component had not hydrated. It had — the countdown was ticking. **The instrument was wrong, not the app.** Twice this session the JS measurement channel wedged and returned all-zero rects while the page was fine. Cross-verify with a screenshot before believing a layout is broken.
