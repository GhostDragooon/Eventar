### WP1 — Hygiene fixes

- **H1 — pending banner link is signedIn-aware** (`app/(public)/checkin/confirm/page.tsx`). Threaded `signedIn` into `CheckedInView`. Signed-in visitor's pending banner now links to `/account/claim` directly; signed-out still goes via `/account/sign-in?next=/account/claim`. The RPC's `pending` state only fires when `user_id IS NULL`, but a signed-in caller with a lingering guest registration still gets it — forcing them through an OTP loop was a dead end.
- **H2 — nested `<form>` split in `ProfileClient.tsx`.** The Licences declare `<form>` was rendered inside the profile edit `<form>`. Invalid HTML; a submit inside the inner form could trigger both handlers. Restructured to sibling forms: Licences is now its own `<section>` after the profile form closes. Same SectionCard chrome, same visual result.
- **H3 — "Link past registrations" link hidden when `unlinkedCount === 0`** (`AccountClient.tsx`). Was permanently rendered; sent people to a page that then rendered a soft "nothing to link" empty state.
- **H4 — unified claim-error dictionary** (`app/account/claimErrorCopy.ts`, new). AccountClient and ClaimClient were rendering different copy for the same server errors (notably `email_unverified`). Both now import `claimErrorCopy()`.
- **H5 — genuine empty state for accrediting bodies** (`ProfileClient.tsx`). When `activeBodies` is empty, the picker + declare form are replaced by a message: "No accrediting bodies are open for self-declare right now. Please contact the event organizer." Pre-fix showed a disabled `<select>` with the inscrutable placeholder "No bodies available".
- **H6 — declare-licence success message extended** with the "if you've already checked in today, reopen your pass to see updated credit status (or wait for reception)" hint.
- **H7 — 'missing' credit banner honesty for signed-in attendees.** Was "Please see reception before you leave." — but a signed-in attendee's most likely `missing` cause is an F1–F5 gate they can fix themselves (profile / licence / consents). Now: signed-in → "check your account, or see reception if everything looks correct." Signed-out → unchanged (reception is the right escalation).
- **H8 — display-language helper.** "Saved for future emails and materials. Site UI is English for now." — sets the honest expectation.

### WP2 — Credential field alignment

- **C1/C2 — body-aware credential label.** New `credentialLabelForBody(shortName)` helper at the bottom of `ProfileClient.tsx`. `HKAM` and every `HKC*` short_name (all 15 HKAM Colleges) → **Fellowship number**. `MCHK` and `AHP*` → **Registration number**. Anything else / no body picked → **Membership / registration number** (the HK-neutral generic). Small string-prefix map; upgrade path: move to a column on `accrediting_bodies` when a body needs wording the short_name can't infer. Tagged with a `ponytail:` comment naming the ceiling.
- **C3 — helper text under the credential field**: "The number your college or council uses for you — the same one you'd use on a CME/CPD claim form."
- **C4 — self-declared honesty line** under the licence list (only rendered when at least one row is `declared`): "Self-declared. Eventar can release points for this body; this is not the same as verification by the college or council." Complements the status pill's aria-label.
- **C5 (track / cycle_started_on)** — deferred per Ivan's minimum surface. RPC accepts null for both.
- **C6 — Primary badge is per-body, not per-caller.** Was `licences.length > 1` (any second licence, at any body, showed Primary on the primary row). Now `bodyCount > 1` computed per row — a lone licence at HKCP alongside a lone licence at MCHK correctly shows no badge on either. Two HKCP licences → Primary on the primary row.
