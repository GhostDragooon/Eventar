## Bug found and fixed during backtest

**`email_log` status constraint rejected `'skipped'`.** The `email_log_status_check` only allowed `queued|sent|failed`. The walk-in's `status: 'skipped'` insert was silently rejected (the code didn't check the return). Fixed:
1. Migration `20260913000000` adds `'skipped'` to the constraint
2. Action now checks insert error and logs on failure

The migration was first applied directly via `psql` against the local stack during live backtesting, then registered properly in Supabase's migration history via `supabase migration repair --local --status applied 20260913000000` so `supabase migration list --local` shows it in sync (no drift between the migration file and what's tracked as applied). Verified the live constraint definition on disk matches the migration file byte-for-byte. **Not applied to Seoul (production)** — that requires `supabase db push --linked` and is called out as a next step below, pending explicit go-ahead.
