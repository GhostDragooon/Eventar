## Bug found and fixed during backtest

**`email_log` status constraint rejected `'skipped'`.** The `email_log_status_check` only allowed `queued|sent|failed`. The walk-in's `status: 'skipped'` insert was silently rejected (the code didn't check the return). Fixed:
1. Migration `20260913000000` adds `'skipped'` to the constraint
2. Action now checks insert error and logs on failure
