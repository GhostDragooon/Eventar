   ```sql
          cl.attestation_status, cl.effective_date, cl.created_at

   join public.users u               on u.id  = cl.user_id
   join public.accrediting_bodies ab on ab.id = cl.body_id
   where cl.event_id = '<Event ID from the seed banner>'
   order by cl.chain_seq;
   ```

## Reset procedure (between rehearsals/meetings)
`scripts/demo/reset-demo.ts` (built): local stack only — tear down the demo rows, re-seed, verify chains green. **Reset regenerates the event and every registration code**, so anything rendered from the previous seed is now stale: after each reset you MUST re-run `render-emails.ts` (step 5) and re-note the new `DEMO PASS CODE`/window the seed prints — the phone's old QR and the memorised code will "Code not recognised" at Beat 4 otherwise. Reset clears `credit_ledger` and every licence outright (superuser, local only), then re-declares and re-verifies Karen Lau's HKAM licence on her existing demo account — so **after a reset the ledger is empty and Beat 4.6's row is the only one there**, no sifting required. **Never run demo flows against the live Seoul/Singapore projects: `credit_ledger` is append-only by design; demo rows there would be permanent residue in a regulator-facing table** (reset-demo enforces this with a hard `localEnv()` guard that throws on any non-127.0.0.1 target).

**Recovering a missed credit without a full reset** — `reconcile-event.ts` re-runs issuance for every attended registration and is idempotent, so it is safe to run live (a second run reports `already`, never a duplicate). It does NOT load `.env.local`, so pass the local stack's env explicitly — do **not** `source .env.local`, which points at live Seoul:
```bash
eval "$(supabase status -o env | grep -E '^(API_URL|SERVICE_ROLE_KEY)=')" && NEXT_PUBLIC_SUPABASE_URL="$API_URL" SUPABASE_SERVICE_ROLE_KEY="$SERVICE_ROLE_KEY" pnpm exec tsx scripts/cpd/reconcile-event.ts '<Event ID from the seed banner>'
```
It prints the target URL as its first line — confirm it says `127.0.0.1` before reading anything else. Note its per-row output is registration UUIDs, not names (Hard Rule 10), so it is safe to paste into a ticket.
