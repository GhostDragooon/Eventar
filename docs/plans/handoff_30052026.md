### 🔴 Security regression caught by dev-review (`56983c1`)

The earlier RPC fix (`20260529115302`) used `CREATE OR REPLACE`, which **discards**
the `proconfig` search_path pin that `fix_security_lints` had set via a separate
`ALTER FUNCTION ... SET search_path`. That silently reverted
`create_event_with_blocks` to a role-mutable search_path — the
`function_search_path_mutable` advisor fired again. Fixed durably by putting
`set search_path = public, pg_temp` **inline** in the function definition
(migration `20260530053034`), applied to remote, advisor verified clear,
proconfig now `["search_path=public, pg_temp"]`. **Lesson: any CREATE OR REPLACE
of a pinned function must carry the `set search_path` inline or it loses the pin.**

## Architecture decisions worth remembering

1. **Time state is minutes-since-midnight, not hours.** `DateTimeValue` is
   `{ date, startMinutes, endMinutes }`; agenda blocks keep `start/end` as HH:MM
   strings (so `NewEventForm`'s `${date}T${b.start}:00` ISO builder is untouched)
   with a `hhmmToMinutes`/`hhmmFromMinutes` adapter at the picker boundary. Snap
   to 15 is guaranteed by the picker only emitting `:00/:15/:30/:45`.

2. **Pickers expand INLINE, not as floating popovers** (user's explicit choice).
   Root cause they were fixing: base-ui's `Accordion.Panel` measures
   `scrollHeight` only when `open` toggles (no ResizeObserver) and clamps with
   `overflow-hidden` + fixed height — so an absolute popover, or content that
   grows after open, gets clipped. Solution: pickers render in-flow, AND
   `AccordionContent` got an opt-in `unconstrained` prop that drops the fixed
   height + overflow-hidden (sacrificing that section's slide animation). Applied
   to the Date & Time + Agenda sections only. **If you ever want the slide
   animation back on those sections, the alternative is portaling the picker
   popover instead (base-ui has a `popover` primitive with portal + positioner).**

3. **Envelope validation lives client-side now.** `agendaValid(blocks,
   eventStartMinutes, eventEndMinutes)` runs the "block fits inside event window"
   check so Publish disables + the block reds out *before* submit, instead of the
   server rejecting opaquely. Fail-visibly at the boundary closest to the user.
