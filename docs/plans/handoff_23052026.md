   - Realtime cross-tab is the highest-value smoke step — verifies that `supabaseBrowser()` cookies → channel JWT works as expected.

2. **Supabase migration history drift cleanup** — Task #23.
   - **What:** 3 local-only files (`init_registrations`, `init_email_log`, `fix_security_lints`) vs 4 remote-only mystery rows in `supabase_migrations.schema_migrations` (timestamps `20260519171902`, `20260519172254`, `20260520174601`, `20260520174942`).
   - **Why blocking later:** must be reconciled before Phase 8 (Vercel deploy) so CI's `db push` doesn't refuse the deployment.
   - **How:** first query the 4 mystery rows' contents via Dashboard SQL editor (`select * from supabase_migrations.schema_migrations order by version`); then `supabase migration repair --status applied/reverted` as appropriate; OR resync by `db pull` and committing what's missing.

3. **Host-header spoofing on QR origin** — Task #13.
   - **What:** `lib/qr.ts::buildEventQrPng` derives `origin` from `x-forwarded-proto` + `host` request headers (pre-existing pattern from Phase 3). A request with `Host: evil.com` produces a QR pointing to `evil.com/events/[id]`. Same pattern in 3 call sites now (staff QR download, public event page QR, public poster page QR).
   - **Severity:** Low — requires an attacker to socially distribute the poisoned poster. Pre-existing, not a regression.
   - **Fix:** Add `NEXT_PUBLIC_SITE_URL` env var; pass through call sites; fall back to headers for local dev. Required before Phase 8 deploy.

### Strategic / known debt

4. **Cross-event scan on staff tablet succeeds intentionally** — A manager scanning a code from another organiser's event gets a success toast with that event's title. Documented in `markAttended` comments + Phase 4 vault note. Could be tightened later by adding an event-ownership gate when `params.id` (URL) doesn't match `event.id` (resolved from code) — would close the "scanned the wrong QR by accident" hole at the cost of breaking the manager-multi-event use case.

5. **No rate limit on `selfCheckIn`** — Public action, code-as-bearer-token, ~0.005% brute-force success per try. Low real-world severity until many events accumulate. Add a per-IP rate limit (Vercel KV / Upstash / Postgres-based) before Phase 8 deploy if you want to be belt-and-braces.

6. **`createBrowserClient` is called per-render now** — `supabaseBrowser()` constructs a fresh client inside the `useEffect`. supabase-js handles this gracefully (it's cheap; the channel is what owns the socket) but a long-lived shared instance via a React Context would be cleaner. Not blocking; revisit if Phase 5/6 spawns more Realtime callers.
