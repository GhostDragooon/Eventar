## Frontend↔backend map (the key analytical deliverable)

Grounded in **`docs/plans/2026-07-23-cpd-mvp-architecture.md`** — the authoritative full-product block map (K1–K3 · B1–B9 · surfaces), each capability carrying a build-state and tier. Verified its tags against reality (routes, 18 tables, functions). **Headline: the CPD credit engine IS live** (publish → self-check-in → `award_attendance_credit` issuance, hash-chained, idempotent, backtested and on `origin/main`).

**Key architectural fact:** `award_attendance_credit` resolves identity at **award time** (registration email → auth.users → active licence @ event body). There is **no read-time query** that surfaces a registrant's licence status back to the organiser — that one missing view is what nearly every organiser eligibility feature in the mockup depends on.

| Mockup surface | Backend | State |
|---|---|---|
| Public single-track · Organiser Events (Agenda/Check-in/CPD&Accred)/publish/roster/survey/analytics/QR | S-Public · B1 + CPD-config + B3 issuance | ✅ shipped (frontend frozen) |
| Organiser roster eligibility / **Participants** (licence status) | read-time resolve registration→user→active licence | **not built — new read view (data exists)** |
| Organiser Communications scheduled sends | B5 real send + pg_cron | 🔵 deploy-gate |
| Organiser Analytics funnel | page-view tracking | ⚪ (not in B1) |
| **Practitioner app (entire)** | **S-Attendee** | 📋 post-M4 — data exists (B2/B3/K1), surface not built |
| Practitioner Overview compliance math | B3 **evaluator + versioned body_rules** | 🔒 **gated on Q26 / body review** |
| Practitioner Evidence locker · Share & verification | B6 | 📋 planned (S5) — no table / no share-link |
| Practitioner login / accounts | K1 self-serve attendee accounts | ⏳ substrate ⚪ — prerequisite |
| Public multi-track | B1 per-session CPD + sessions/rooms/roles schema | ⚪ (not built) |

**Prioritised gaps:** (1) organiser read-time licence-resolution view — the one non-gated, high-leverage backend piece, backed by existing data; (2) the whole S-Attendee serve layer; (3) B3 evaluator (Q26-gated); (4) Evidence + Share (B6, S5); (5) multi-track schema; (6) pg_cron scheduling + analytics tracking; (7) self-serve onboarding; (8) registry completeness (OT_BOARD + HKAM's 15 colleges unseeded — flagged in `handoff_26072026`).
