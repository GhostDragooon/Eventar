## Decisions locked

### §7a — instructional color (supersedes one-color-one-meaning strict)

| Color | Means | Where |
|---|---|---|
| **Green** | Open / available / go | Registering pill, Live pill, any "you can act now" |
| **Accent blue** `#0070F3` / `#3291FF` | Action / where to click | Primary CTAs, key numerals, active section indicators, section ID chips |
| **Amber** | Hold / draft / pending | Draft pill, popped reg code, "needs venue + date" cues |
| **Red** | Stopped / error / destructive | Form errors, Cancelled pill |
| **Neutrals** | Off / done / context | Completed pills, decorative chrome |

Patterns doc `eventar-design-patterns.md §7a` is now **stale** and needs a rewrite to match. That's an open item for the next session.

### Typography

- Geist + Geist Mono confirmed locked
- Mono **restricted to numerical data only** — date stamps, countdown digits, agenda times, stat numerals, registration codes
- Labels / eyebrows / section IDs / role tags are **Geist sans uppercase** with `letter-spacing: 0.18–0.22em`
- Hero H1: 48–54px Geist 900 with `-0.045em` tracking
- Section H2: 22–24px Geist 800 with `-0.025em` tracking
- 4-point spacing scale enforced

### Composition patterns

- **Hero band** — dark gradient + two radial blooms + dot-grid + 2px accent rule at top
- **Hero corners** — top-left pills · top-right countdown · bottom-left venue · bottom-right date stamp
- **Top padding 22px** (halved from the originally-comfortable 44px)
- **Partner row** — collapsed horizontal strip at the bottom of the hero · category labels inline · hairline dividers between groups · sponsors label in accent · `+ N ▾` expand chip
- **Speakers** — 112px circular portraits · keynote gets 6px accent gradient ring · role label uppercase tracked above name
- **Scoreboard countdown** — discrete cells with monospace digits + tracked unit labels below
- **Section markers** — accent-blue ID chip + H2 + right-aligned meta
- **Register card** — second dark moment, same gradient family as hero · full-width accent CTA
- **Agenda** — time-anchored 3-col table · current/next row gets accent left border + faint gradient bg
- **Two dark moments per public surface** — hero anchors arrival, register card anchors action

### MVP gates (from MVP Scope)

The two outstanding gaps to the close-loop loop running end-to-end:

1. **Email #2** — personal QR reminder template + action `sendReminderForEvent(event_id)`
2. **Email #3** — survey invite template + action `sendSurveyInviteForEvent(event_id)`

After both ship, the loop runs against `devEmailStub` + localhost. Then Resend / Vercel / pg_cron are plug-and-play swaps.

### Schema additions needed (Wave 5 — not started)

Production code can't render the v10 mockup without:

- `events.hosted_by`/`organized_by` jsonb: extend each entry from `{name, url?}` to `{name, logo_url?, url?}`
- `events.sponsors` jsonb: new field, array of `{name, logo_url, url?, tier: 'title'|'gold'|'silver'}`
- `events.cme_points` int nullable
- `events.accreditation_body` text nullable (e.g. "HKAM")
- `events.edition_code` text nullable (e.g. "CC-Asia 2026")
- `agenda_blocks.topics[].speaker_name` (currently plain string) → upgrade to structured `{name, role, affiliation, photo_url?}`
- Storage bucket `event-hero-images` (already exists from Wave 3) — extend to accept partner logos + speaker photos

### Site-level (revealed by v10's full chrome)

Currently the codebase only has the in-app routes (`/events/[id]`, `/dashboard`, `/login`, etc.). v10 exposed that for a real **website** we'd also need:

- **`/` landing page** — currently redirects to `/dashboard`; for public visitors it should be a marketing landing
- **`/events` list page** — public version of the dashboard
- **`/about`, `/sponsors`, `/cme`, `/contact`** — marketing chrome
- **Real legal pages** — `/privacy`, `/terms`, `/accessibility` (drafts at v0.2 in `docs/legal/`, not published)
- **Top nav with proper sections + Sign in link** (currently just a centered wordmark)
- **Structured 4-column footer** (currently a single-line "By Eventar")

The white-label question (`Commercialisation Proposal` Step 2) implies the society's own branding + nav replaces Eventar's on customer-side deployments. Both layouts need to be supported.
