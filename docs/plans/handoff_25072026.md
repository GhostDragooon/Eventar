## The four real schema mismatches the build itself caught (Stages 1–4, not the plan, not either review round)

1. `entry_type='attendance'` doesn't exist (CHECK only allows `credit_earned|credit_adjusted|credit_transferred|credit_expired|credit_revoked`) — Stage 1's idempotency index was silently inert; re-keyed to `entry_type='credit_earned' AND attestation_status='attendance_verified'`.
2. `attestation_status` CHECK lacked `'attendance_verified'` — widened (Ivan-confirmed) since venue-captured attendance is a distinct, stronger provenance tier than `organiser_attested`.
3. `public.users` has **no email column** — identity resolution had to move into the `award_attendance_credit` SECURITY DEFINER function itself (it can read `auth.users`; the TS layer can't).
4. `practitioner_licences.status` has no `'active'` value — the good-standing state is `'verified'`. Corrective migration `20260724170650`.

## Stage 4 — two bugs only live-browser verification caught

1. **Wrong Supabase project**: main checkout's `.env.local` points at Seoul, not local — `pnpm dev`/`:3000` is a live-Seoul server. Fix: use the `demo-local` launch config (`:3100`).
2. **Kill switch defaulted OFF**: required explicit `CPD_ISSUANCE_ENABLED==='true'`, which nothing set anywhere, so every award silently skipped with nothing logged. Inverted to fail-open (`==='false'` disables), added the missing skip-log, added a regression test.

Re-verified live after both fixes: real browser click → real `credit_earned | attendance_verified | 3 hours | HKAM` row → chain valid → server log confirms `result: 'issued'`.
